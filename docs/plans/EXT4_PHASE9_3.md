# EXT4 Phase 9.3 — Recovery, reuse and interoperability execution

Authorized after Phase 9.2; host-only disposable fixtures. Production journaled
RW stays disabled. This specification records no new test passes.

## Mounted recovery interruption

Select reproducible dirty stable inputs from the verified Phase-9.2 ledgers,
including committed metadata awaiting replay, partial checkpoint, open-unlink,
last-close and linked shrink. Preserve the independent expected durable prefix
and source input hash. Include all twelve geometry/placement combinations.

Inventory every write and flush from actual fresh mounted recovery, including
replay, orphan drain and activation before VFS publication. Apply the calibrated
six persistence profiles to each boundary; retain sector-tear cases separately
from recoverable atomic boundaries. Failed admitted I/O must return an error and
publish no mount. A fresh restart must satisfy the original byte/namespace and
allocation oracle, or a specific independent durable-corruption witness.

Repeat each recoverable interrupted recovery at a declared second boundary.
Keep the second trace and cut identity; never infer repeated-recovery safety
from a single successful retry. Verify final clean freeze and a fresh readback,
with independent Linux bytes, namespace, ownership and unmounted fsck checks.
Bound batches and retain reconstructible sector deltas rather than every full
image. Record exact coverage counts before acceptance.

## Extended histories

Use multiple traditional orphans and linked shrink intents, then block reuse
with distinguishable old/new bytes. Require stale replay and revoked metadata
never to overwrite the reused allocation. Exercise sequence wrap and journal
ring wrap with actual replay provenance. Test valid small journals and resource
admission independently of synthetic transaction-credit exhaustion; unsupported
geometry must reject without writes and must not count as a supported fixture.

## Interoperability

Retain FortressOS-produced committed journals for independent Linux replay.
Retain supported Linux-produced journals, producer commands, raw images and
hashes for FortressOS recovery. The established debugfs zero-tag-UUID conversion
is an explicit fixture-generation boundary; preserve both raw and converted
images. Corruption inputs are never normalized or repaired into acceptance.

## Acceptance and limits

Require complete declared schedules, precise preflight zero-write rejection,
no premature mount publication, preserved cache/taint/barrier semantics and
clean independent audits for every recoverable final outcome. Keep failed
attempts and source/binary hashes outside build. Host success establishes no
guest, USB or physical power-loss claim; those remain Phase 9.4–9.6.
