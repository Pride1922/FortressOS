# Package delivery status

2026-10-24. Tracking only; the original production integration plan is preserved.

The package feature is not ready for production enablement. Private status and
recover have host and native Ring 3 evidence for the finite demo profile;
selector authentication has host evidence. Actual filesystem geometry and
identity checks are now implemented and accepted on disposable host fixtures.
These results do not complete native enrolled-root admission or package mutation.

## Remaining implementation, in dependency order

1. Construct canonical initial IDLE records and the signed descriptor from the
   actual protected inode generations/maps and credential hashes. Read the
   records back through an independent native filesystem adapter before
   committing the TEST selector. Exercise incomplete/mixed publication cuts.
2. Deliver independent TEST selector/policy boot modules, measure actual kernel
   and bootstrap bytes without a hash cycle, and authenticate the selected GPT
   root in the projected-journal preview before any recovery writes. Validate
   namespace contents, lineage, ownership, capacity and rollback floors before
   account-service authentication or root publication. Refuse partial/foreign/
   unreadable enrollment; establish incompatible-kernel exclusion.
3. Integrate native status/acquire/recover/release with that admitted root and
   its lifecycle fences. Repeat owner, credentials, signal/reaper and fresh-boot
   recovery acceptance against enrolled fixtures. The accepted private demo
   backend is evidence for its documented profile, not this integration.
4. Implement the bounded executable/document install and remove paths, immutable
   typed plans, complete reservation/escrow, trust-floor publication, generalized
   completion evidence and ownership-safe removal. CLI mutation remains disabled.
5. Run integrated BIOS/UEFI x SMP=1/4 interruption and repeat-recovery campaigns,
   independent Linux audits, concurrency/open-executable/low-space cases and
   uncertain-I/O refusals. Record boot acceptance separately from preservation.
6. Review all four production gates before enabling bounded production commands.
   Production key selection/provisioning and operational deployment are separate
   explicit decisions; test keys must never become production authority.
