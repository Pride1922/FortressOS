# FortressOS — Core Tools & Compression Subsystem Annex

## 1. Overview & Architecture

FortressOS provides freestanding userland utilities executed in **Ring 3** using standard System V AMD64 ABI conventions without hosted libc runtime (`malloc`, `free`, `printf`). File operations interface directly with the kernel through `tool_syscall` wrappers (`SYS_OPEN`, `SYS_CLOSE`, `SYS_READ`, `SYS_WRITE`, `SYS_STAT`, `SYS_UNLINK`).

The compression subsystem provides `/bin/gzip` and `/bin/gunzip` implementing standard **DEFLATE** (RFC 1951) and **gzip** (RFC 1952). The tools are designed for log rotation, archive creation, package extraction, and secure in-place stream processing.

### Key Architectural Invariants
- **Zero Dynamic Allocation**: The core compression and decompression loops allocate zero dynamic heap memory. All buffers (32 KiB sliding window, canonical Huffman tree arrays, bit-reader/writer buffers, hash tables) reside in static BSS storage.
- **Decompression Bomb (Zip-Bomb) Resistance**: Decompression enforces an unyielding output cap (`GZIP_MAX_OUTPUT` = 100 MB). If emitted bytes reach 100 MB or if trailer ISIZE indicates overflow, decompression aborts immediately with a non-zero exit status, cleans up partial destination files, and prevents OOM panics.
- **Strict Stack Discipline**: Stack frames are strictly bounded (`-Wframe-larger-than=1024`, all functions <= 400 bytes stack usage), matching the kernel and SSH cryptography discipline.
- **Full DEFLATE Interoperability**:
  - Decompression handles Stored blocks (`BTYPE 00`), Fixed Huffman blocks (`BTYPE 01`), and Dynamic Huffman blocks (`BTYPE 10`). It seamlessly decompresses archives generated by GNU/Linux `gzip -c` and zlib.
  - Compression utilizes an LZ77 streaming match finder (3-byte hash table with 32-node max chain limit) and Fixed Huffman encoding over a 32 KiB sliding window. It achieves over 100:1 compression ratio on repetitive data and decompresses identically under GNU/Linux `gzip -d`.
- **CRC-32 & Trailer Verification**: Standard IEEE 802.3 / RFC 1952 CRC-32 (polynomial `0xEDB88320`) table-driven calculation verifies data integrity against uncompressed payloads. ISIZE and CRC-32 mismatches fail closed with distinct diagnostics.

## 2. Command Line Utilities

### `/bin/gzip`
Compresses files or standard input into RFC 1952 `.gz` archives.

**Syntax:**
```bash
gzip [-c] [-d] [-f] [-k] [-1..-9] [--help] [FILE ...]
```

- `-c`, `--stdout`: Write compressed stream to standard output; preserve original files.
- `-d`, `--decompress`: Decompress input files (equivalent to `gunzip`).
- `-f`, `--force`: Overwrite existing output files without prompting.
- `-k`, `--keep`: Keep (do not delete) input files after successful operation.
- `-1` .. `-9`: Accepted compression speed/ratio presets.
- With no `FILE` or when `FILE` is `-`, reads standard input and writes standard output.
- Default behavior: replaces `FILE` with `FILE.gz` upon success (unlinks source).

### `/bin/gunzip`
Decompresses RFC 1952 `.gz` archives or standard input into raw streams.

**Syntax:**
```bash
gunzip [-c] [-f] [-k] [--help] [FILE ...]
```

- Strips `.gz` extension to derive output filename (e.g. `archive.tar.gz` -> `archive.tar`).
- Validates magic header (`0x1F 0x8B`), compression method (`0x08`), flag byte, and trailer CRC/ISIZE.
- Default behavior: replaces `FILE.gz` with `FILE` upon success (unlinks `.gz` source).

## 4. Visual Text Editor (`/bin/nano`)

`/bin/nano` is a standalone, bounded in-terminal visual text editor executed in Ring 3 with zero heap allocations (pure static BSS allocation model, 256 KiB pool size, max 4096 rows).

### Mouse Support Architecture (Phase 4 / v2.2)
- **Standard SGR 1006 Extended Mouse Mode**:
  - Emits `\x1b[?1000h\x1b[?1006h` on initialization; restores terminal via `\x1b[?1000l\x1b[?1006l` on exit.
  - SGR framing format: `\x1b[<B;X;YM` (press) and `\x1b[<B;X;Ym` (release).
- **Interactive Editing Operations**:
  - **Click-to-Position**: Viewport clicks convert 1-based screen coordinates $(X, Y)$ to file row `cy` and character column `cx` via `nano_render_to_col()`, correctly subtracting line number gutter width (`digits + 3`) and expanding tab stops (8 columns).
  - **Scroll Wheel**: Smooth 3-line viewport scrolling per wheel tick (wheel up button 64, wheel down button 65) with bounded cursor repositioning.
  - **Shortcut Legend Bar**: Clicks on row $H$ directly dispatch editor actions (`^O Save`, `^X Exit`, `^W WhereIs`, `^R Replace`, `^G GotoLine`, `^Z Undo`, `^Y Redo`).
- **Terminal & Shell Isolation**:
  - Kernel console (`g_console`) monitors ANSI private modes `?1000h`/`?1006h`.
  - Mouse events from xHCI USB HID boot mice are only encoded and injected (`input_inject_bytes()`) when an application explicitly requests mouse tracking, preventing raw escape characters at the `fortress>` shell prompt.
- **Verification Matrix**:
  - `make test-nano-host`: 100% PASS under ASan/UBSan (unit tests for SGR parsing, tab column translation, coordinate clamping, scroll wheel, and shortcut legend dispatches).
  - `make test-nano`: 100% PASS across BIOS and UEFI 13 integration stages (`scripts/test_nano.py`), verifying live SGR mouse clicks, viewport scrolling, and shortcut bar exit.
  - `make test-nano-ssh`: 100% PASS across BIOS and UEFI OpenSSH client sessions.
