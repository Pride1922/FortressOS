# EXT4 Phase 3 — allocation and extent mutation engine

Implemented 2026-10-03 as an internal workbench with host sanitizer and Linux interoperability gates. Production stays ext2; `ext4_mount_rw` still returns EROFS and VFS mutation callbacks remain absent. No device discovery, USB eligibility, raw-write gate, DMA ownership, boot ordering or lock-rank contract changes.

Implementation: `src/fs/ext4_mutate.inc`, included by the actual `ext4.c` translation unit, with internal contracts in `ext4_engine.h`. A workbench exclusively owns its admitted device and cannot coexist with an RO mount or another workbench. Construction allocates the fixed workspace before use; staging and commit never allocate fallback memory. Failed admission releases everything and writes nothing.

Delivered operations:

- Checksum-validated block/inode bitmap allocation, reserved-metadata exclusion, bitmap padding and group boundaries, primary superblock/group counters and checksums. Logical UNINIT bitmaps are synthesized from the fixed layout; inode allocation requires an eagerly zeroed table. Regular/directory inode reservation maintains free/unused inode and directory counters, clears stale fields, assigns a new generation and writes inode checksums. Only provisional, empty, unlinked inodes owned by this workbench can be released.
- Regular-file allocation into holes with at most 64 KiB newly zeroed data per operation, contiguous-run merging, initialized extent length limits and 8 GiB logical-size admission. Existing unwritten mappings are preserved; overlapping growth is rejected. Partial-block writes and unwritten conversion are Phase 4.
- Bounded whole-tree rebuilding into newly allocated leaves/indexes: inline root, depth-1 promotion/leaf splitting, depth-2 promotion and index-key propagation. Sorted canonical extents produce the required node layout/checksums, with inode size and 512-byte `i_blocks` accounting updated. There are at most 4096 extents; this cap prevents a further index fan-out split from being reachable in this profile.
- Complete-block tail removal, extent shortening, tree collapse and delayed reclamation of replaced nodes/data. No freed block is reused inside the operation that removes its references. Growth, trim and inode reservation are staged without writes, can be aborted before commit, and fail with deterministic ENOSPC/EFBIG rather than publishing a partial tree.

Write order: persist a dirty primary superblock; zero newly exposed data and write new tree blocks; persist allocation bitmaps/counters while holding all pending frees allocated; publish the inode root/size; only then persist the frees and final counters. Each phase has a barrier. Failure after commit begins permanently taints the context, stops subsequent mutations/clean-success claims and does not promise rollback. Closing leaves dirty state; explicit successful finish flushes and marks clean only with no pending plan or outstanding provisional inodes. Dirty workbench/RO remounts reject. This is E4-A ordering, not a journal or power-loss recovery guarantee. A failed clean-state write/barrier cannot be advertised as a successful clean shutdown, even if the device accepted the clean-state sector.

The hard workspace cap is 64 distinct filesystem block images. Final and interim allocation states use those same buffers; pending frees are held by reversible staged bit/counter changes, not another image cache. Reference/checksum/counter preflight occurs before the first write. Rebuilding a 4096-extent Linux-generated tree used 55/31/19 images at 1/2/4 KiB blocks in the retained fixtures. Operations touching more groups/GDT pages than the 64-image budget allows reject before writing. Whole-file deletion is therefore bounded, not unlimited: Phase 4 must admit/reject oversized operations explicitly; restartable orphan-backed deletion belongs to the journal milestone.

Validation latency work replaces pairwise physical-reference overlap checks with heap sorting and uses binary search over sorted metadata reservations. One verified bitmap is cached only within one tree-validation pass and invalidated at every new root traversal. The complete tree is still validated before a map or changed root can be published. Before this change, the maximum-map mock staging measurement was about 27 ms; after it, the retained sanitizer run measured approximately 1.3 ms on these fixtures. These are hosted CPU/memory-disk measurements, not kernel IRQ or hardware timing. A commit has at most 128 metadata block writes, 64 KiB zeroed data, the dirty-superblock write and five barriers (at most 1154 sector writes for the supported geometries). Device latency and scattered group access still require measurement before RW integration; no real-time/physical latency claim is made.

Commands actually run:

```text
wsl -d Ubuntu-24.04 -- make test-ext4-alloc-host
wsl -d Ubuntu-24.04 -- make test-ext4-read-host
wsl -d Ubuntu-24.04 -- make test-ext4-read
wsl -d Ubuntu-24.04 -- make test-ext2
wsl -d Ubuntu-24.04 -- make
git diff --check
```

Mutation gate: six 1/2/4-KiB × 512/4096-sector cases plus six maximum-map cases, actual implementation under ASan/UBSan. Disposable 32 MiB images use the exact feature profile, 4096-block groups and a small inode count to force both block and inode group transitions. Tests prefill free data blocks with stale 0xA5 bytes and prove newly visible bytes are zero. They cover 1 MiB growth, contiguous merging, interleaved physical fragmentation, cross-group bitmap initialization, root promotions, leaf splits, depth-2 trees, shrink/collapse, exact block-allocation-set restoration, regular/directory inode reservation/reuse/release, logical offsets above 4 GiB, write-free abort, exclusive ownership, dirty remount rejection, all four construction allocation failures, allocation-free staging/commit, full bitmap ENOSPC and the 64-image credit boundary.

Fault matrix: every staging read for small growth and inode reservation; first/middle/last staging reads for representative depth-2 growth/trim; every commit read, sector write and barrier for those representative mutations; write-accepted-but-error-returned cases; every finish read/write/barrier. Tainted contexts issue no later writes. An independent byte-level barrier oracle walks the current on-disk inode/tree and checks that all live referenced blocks remain allocated, including before pending frees are released. This synchronous fake disk does not simulate volatile caches, torn sectors, arbitrary power cuts or replay; Phase 6 adds that infrastructure.

Linux audits: `e2fsck -fn` on every final image plus clean snapshots of 1 MiB growth, root promotion, depth-2 growth, cross-group allocation and high-offset growth. Independent `debugfs` dumps are compared byte-for-byte with generated expected data; maximum-map dumps preserve all old payload bytes and append zero-filled blocks. The high-offset fixture is checked by fsck/stat and read through the actual RO callback without creating a 4 GiB host dump. Counter, inode-checksum, extent-tail and neighbor-sector preservation errors therefore cannot be hidden by truncating every file before the audit.

Phase 4 handoff: attach one workspace to an admitted RW mount and its authoritative inode state; invalidate/replace RO map caches on mutation. Add byte writes, EOF-gap handling, unwritten conversion, timestamps, directories and VFS operations. Reject active-target unlink/replacement according to the frozen VFS lifetime/replacement contracts. For deletion, persist inode/tree reference removal before freeing data/tree blocks, remove namespace references before freeing the inode, and reject credit overflows before the first write. Namespace publication/final link counts and release of detached existing inodes require the Phase-4 layer; the provisional-inode allocator cannot silently free a linked inode. Keep RW hardware dispatch disabled until integration, durability and timing gates pass.

References: [Linux group descriptors](https://www.kernel.org/doc/html/latest/filesystems/ext4/group_descr.html), [inode layout](https://www.kernel.org/doc/html/latest/filesystems/ext4/inodes.html). Primary on-disk metadata is maintained; this phase adds no repair path from damaged primary metadata or journal replay.

Final evidence: `build/ext4-phase3/run-ilpye849/manifest.json` (six geometry and six maximum-map cases), `build/ext4-phase0/fixtures-xqua9o9v/manifest.json` (RO host regression), and `build/ext4-read/run-v74razo6/manifest.json` (RO BIOS/UEFI 6/6). Strict build, ext2 host regressions and diff whitespace check also passed. Initial failed or superseded workbench runs remain in their unique directories.
